### Data safety answers

The app has no backend, analytics or crash reporting. Data goes only from the device to crates.io / GitHub because the user asked for it.

- **Does the app collect or share user data?** Yes, minimal:
  - *Personal info → User IDs*: the crates.io user ID and login are fetched from crates.io and **stored on device**. Purpose: App functionality. Not shared.
  - *App activity / Authentication*: the crates.io session cookie, sent only to crates.io.
- **Encrypted in transit?** Yes (HTTPS only)
- **Can users request deletion?** Yes: sign out, or clear app data / uninstall. Nothing is kept server-side by the app
- The GitHub password is typed into GitHub's own page in a WebView; the app never reads it

## Build and signing

| Item | Status |
| --- | --- |
| Target API level | ✅ targetSdk 37 (meets the current Play requirement) |
| Android App Bundle | `./gradlew bundleRelease` → `app/build/outputs/bundle/release/app-release.aab` |
| Upload key | ❌ **Needed.** No `signingConfig` yet. Create an upload keystore (`keytool -genkeypair -v -keystore upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`), keep it out of git, wire it into `app/build.gradle.kts` from `~/.gradle/gradle.properties` or CI secrets, and enroll in Play App Signing |
| versionCode / versionName | 2 / 2.0. Bump `versionCode` on every upload |
| Package name | `io.github.andraantariksa.crates`. Permanent once published, so confirm it before the first upload |
| R8 / minify | Off. Optional: turn on `isMinifyEnabled` for a smaller download (Moshi codegen and Retrofit ship their own keep rules) |
| Permissions | `INTERNET` only |

## Trademarks

"Rust" and "crates.io" are Rust Foundation trademarks. The listing keeps them out of the app name and icon, says the app is unofficial, and uses the names only to describe what the app connects to (see the [Rust trademark policy](https://foundation.rust-lang.org/policies/logo-policy-and-media-guide/)). The icon is original pixel art (crates on a pallet), not the crates.io logo.
